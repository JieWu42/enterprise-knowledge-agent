# 实现方案与取舍

采用 Python 标准库直接实现单 Agent。未使用 LangGraph/LangChain；本题小型循环无需额外运行框架，更便于检查真实模型动作与执行边界。

## 调用流程

问题与历史 → 模型选择工具 → 校验参数 → 检索/读取 → 将实际结果交回模型 → 模型补查、重试、请求澄清或结束 → 最终来源与结构校验。

执行器不按“冲突/失败用例 ID”路由模型动作。检索关键词、读取对象、是否重试、是否补查及最终结论均由真实模型根据对话和工具观察选择。离线 Mock 是显式的固定流程，不作为决策效果证据。

search_documents 返回候选文档 ID、范围、日期、分数、命中摘要与全部可读段落编号 available_paragraph_ids。read_document 返回准确段落和可用段落编号；请求不存在段落时，错误也返回正确编号，整次读取仍为失败，不返回部分原文或授权引用。只有成功读取的段落加入本次运行的证据集合，检索元数据、历史回答或上次运行不会自动授权引用。

明确区分规则概览与个人适用问题：用户要求比较规则时，可直接按适用范围列举；用户询问自己的期限或资格且缺少必要条件时，由模型请求澄清，不能把列举分支当作已解决个人问题。代码没有按“境内/境外”等关键词硬编码决策。

## 检索

将中文和字母数字文本归一化后构建字符二元片段，按问题片段与文档标题、范围、最佳段落的重叠占比排序。top_k 可在 1 至 8 之间选择，不自动只保留最新版。此分数不是语义置信度。

追加的领域同义词扩展保留原查询，将词表新增字符片段按 0.5 权重参与排序，重复片段不重复加分；可通过 --no-query-expansion 关闭。工具返回 applied_aliases，Trace 记录 retrieval_config 与词表摘要。词表不包含文档答案和评测标签，相关实验见 [检索改进](09-retrieval-improvement.md)。

优点是无第三方依赖、可解释、适合小型制度库。局限是同义词缺乏字符重叠时仍会漏检，常用片段也会带来噪声；模型可改写查询，但不能保证找全。更大资料库应以新测试集比较分词/BM25、向量及混合检索后再决定升级。

## 模型接口

通过 urllib 调用 DeepSeek Chat Completions，使用原生 tools/tool_calls 及 tool_call_id 回传结果；没有让模型“假装工具执行”。接口依据 [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/) 和 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。请求关闭 thinking，不采集隐藏思维内容。Trace 保留动作说明、结构化调用和观察。

模型标识、服务端实际模型名、token usage、源码摘要、资料摘要和输入均记录；密钥与授权头不写入 Trace。请求使用 temperature=0，但不能据此保证完全确定性。

## 执行与输出保障

默认最多 8 次模型请求、10 次工具调用，失败调用也计数；批量工具调用逐个检查剩余额度。预算耗尽返回 incomplete/step_limit。每次模型 HTTP 请求设置 60 秒网络超时，不自动暗中重试。

最终校验检查字段类型、状态、缺口、引用文档、版本、段落是否成功读取及 quote 是否为连续原文。answered 有缺口会被退回，要求模型修正或返回未完成；partially_answered 要求同时有证据和缺口。

来源校验不等于语义蕴含验证。模型即使引用存在，也可能作出不受引文支持的推断；需要人工逐项复核及进一步评测。

工具为同步的本地内存操作，没有单独的可中断超时机制；网络超时为连接/读操作超时，不是严格的整次任务墙钟上限。本版本不声称具备生产级 Runtime、对抗注入保障或并发服务能力。
